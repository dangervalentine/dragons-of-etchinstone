# Implementation Plan: UI Polish and Presentation Overhaul

**Branch**: `001-ui-polish` | **Date**: 2026-10-13 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-ui-polish/spec.md`

**Note**: This template is filled in by the `/speckit-plan` command; its definition describes the execution workflow.

## Summary

Replace the game's single scrolling column of labels and buttons, which is torn down
and rebuilt after every tap, with persistent screens built from small widgets: card
and Encounter faces laid out like the printed cards, a visual outcome preview, a
fixed seven-region play screen in a single landscape arrangement (the game is
landscape only, per the spec's Clarifications), and an animated, skippable
resolution sequence. The rules engine is not touched. The UI snapshots the
game before and after each action and a pure sequencer turns the difference into the
ordered steps the view plays, so the model is always already correct and animation
can only ever be late, never wrong.

## Technical Context

**Language/Version**: GDScript, Godot 4.7.2 (standard build)

**Primary Dependencies**: Godot engine only. New bundled assets: two OFL font
families (Cinzel, Alegreya Sans) and additional generated SVG icons. No add-ons.

**Storage**: One small local settings file (motion preference, last game options).
No saved games.

**Testing**: The existing headless runner (`tools/test.sh` → `tests/run.gd`), with
new tests for the pure UI model; a new headless UI check script that drives the real
screens across a size matrix; `tools/shot.gd` for a screenshot matrix; manual and
observer checks in [quickstart.md](quickstart.md).

**Target Platform**: Web (HTML5), Android, iOS; desktop for development.
Compatibility renderer, as today.

**Project Type**: Single-project game client (mobile and web), no backend.

**Performance Goals**: 60 fps during animation on a mid-range phone from the last
four years; visible press feedback within 0.1 s; resolution sequence at most 3 s
and skippable in under 0.5 s.

**Constraints**:
- `engine/`, `data/cards.json` and the existing `tests/test_*.gd` files are not
  modified (FR-037, SC-012).
- No scanned artwork or rulebook text ships (spec assumption; reference material is
  git-ignored).
- Minimum text 22 design units, minimum tap target 88 design units.
- Landscape only: one arrangement on every target. The mobile apps are locked to
  landscape in either direction. No portrait arrangement is built.
- Offline; no network at runtime.

**Scale/Scope**: 3 screens, 5 overlays, about 15 widgets, 5 pure model modules,
about 25 new icons. `ui/main.gd` (876 lines) is replaced by roughly 25 files of 50
to 250 lines each.

**Structure Decision**: Keep the single Godot project and its existing top-level
layout. All new code goes under `ui/`, split by responsibility into `theme`, `model`,
`screens`, `widgets`, `overlays` and `fx`. The `model` folder is the seam that makes
the feature testable: it has no node dependencies, mirrors how `engine/` is already
structured and tested, and is the only place that reads the engine.

## Design Overview

Detail is in the Phase 0 and Phase 1 documents; this is the shape.

**Data flow**

```text
input ─▶ intent ─▶ root ─┬─ draft-only? ─▶ TurnDraft ─▶ new ViewState ─▶ widgets update in place
                         └─ game action ─▶ snapshot before
                                           engine call (unchanged)
                                           snapshot after
                                           Sequencer ─▶ StepList ─▶ Animator plays; skip snaps to after
```

**Key decisions** (see [research.md](research.md))

| # | Decision | Serves |
|---|---|---|
| R1 | Persistent, code-built widgets; one play screen for all phases | FR-001, FR-022 |
| R2 | Snapshot-and-diff sequencer; engine untouched | FR-021, FR-027, FR-037 |
| R3 | One Animator; a skipping press is consumed and snaps to the after state | FR-024 |
| R4 | One landscape arrangement, minimum 1280 x 720, growing to use larger screens; nothing scrolls | FR-002, FR-028 to FR-030 |
| R5 | Minimum text 22, minimum tap 88 design units | FR-017, SC-008, SC-009 |
| R6 | Procedural card and Encounter faces in the printed layout; sigils in place of illustrations | FR-011, FR-014 |
| R7 | Cinzel and Alegreya Sans (OFL) | FR-004 |
| R8 | Motion setting following the device by default | FR-026 |
| R9 | Tap to place, hold to inspect, full keyboard set on desktop | FR-016, FR-020 |
| R10 | Glossary keyed by card-data ids, coverage tested | FR-035, FR-036 |
| R11 | Engine suite unchanged, pure model tests, UI check over a size matrix | SC-001, SC-012 |
| R12 | In-place updates, cheap shaders, capped CPU particles | SC-006 |

**Build order**, following the spec's priorities so each stage is shippable:

1. **Foundation**: project switched to a 1280 x 720 base and landscape orientation
   on mobile; tokens, theme and fonts; `TurnDraft` and `ViewState` extracted from
   `main.gd`; layout solver; root and screen switching.
2. **User Story 1**: seven-region play screen, header, Encounter face, preview
   panel, slot row, action bar, at phone size, including the Final Battle with
   seven cards.
3. **User Story 2**: card face and card view with all states; inspect overlay;
   fused pair.
4. **User Story 3**: sequencer, Animator, flight layer, feedback effects, reduced
   motion and the settings store.
5. **User Story 4**: growth to tablet and desktop sizes; safe areas in both
   landscape directions; resize; hover and keyboard; the turn-or-widen notice.
6. **User Story 5**: Title screen, stage banners, Ending screen, leave game.
7. **User Story 6**: glossary and popovers, guided multi-step actions, Soak meter
   and XP purse refinements.
8. **Finish**: screenshot matrix review on all targets, README update.

**Risks**

| Risk | Mitigation |
|---|---|
| The Final Battle at 1280 x 720 has about 8 units of slack | The budget is in research R5 and enforced by the UI check; the commit control can move under the preview to free 96 units |
| A phone browser held upright gets a layout too small to read | Accepted with landscape only: the game stays playable and a notice asks the player to turn the device |
| The diff cannot tell two causes of the same card movement apart | Step derivation is ordered and uses the engine result alongside the diff; a test replays every step list in a seeded game and requires it to reproduce the after state |
| Procedural faces look plain next to the printed cards | Sigils, a patterned Ether field and frame ornament; the sigil's place can later take real illustrations with no layout change |
| Font feature or reduced-motion API behaves differently on a target | Both have named fallbacks (R7, R8) and are checked on each target early in their stage |
| A rewrite of the whole UI regresses a rarely reached path | The UI check plays seeded games to completion through the real screens and compares the end state with the engine-only playthrough |
