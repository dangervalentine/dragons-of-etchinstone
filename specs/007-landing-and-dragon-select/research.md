# Research: Landing Page and Dragon Selection

## 1. Where the subtitle and flavour lines live

- **Decision**: A new `data/flavor.json`, read at runtime by `ui/model/flavor.gd`.
- **Rationale**: The user will rewrite the text by hand after implementation. A small JSON file beside `cards.json` is easy to edit, needs no code change, and is already exported (`include_filter="data/*.json"`). Keeping it out of `cards.json` avoids mixing project-written text with the generated card data (`tools/gen_cards.py`).
- **Alternatives considered**: Adding fields to `cards.json` (regenerated by a tool, edits could be overwritten); constants in a `.gd` file (editing text means editing code); a file under `reference/` (excluded from exports, so the game could not read it).

## 2. Behaviour when the file or a line is missing

- **Decision**: `Flavor.subtitle()` falls back to the existing tagline, `Flavor.line(id)` to `""` (the card then shows name and title only). A test asserts the shipped file has a subtitle and a line for every dragon in `cards.json`.
- **Rationale**: A hand-edited file can be broken; the game must still open. The test catches it before shipping.
- **Alternatives considered**: Failing loudly at startup (too harsh for a text typo on a phone build).

## 3. Splitting the screens

- **Decision**: `title_screen.gd` becomes the landing page and keeps its name; a new `dragon_screen.gd` takes the dragon choice. `RulesScreen.back()` already emits `setup_dragon`, which will now show `DragonScreen`.
- **Rationale**: Every path that ends at the title (`to_title`, `records_back`, `leave`) then reaches the landing page with no further change, satisfying FR-015.
- **Alternatives considered**: Renaming `TitleScreen` to `LandingScreen` (more churn in `main.gd`, `ui_check.gd`, `shot.gd` for no behaviour gain).

## 4. Showing only the chosen dragon's stats

- **Decision**: Cards carry head, name, title and flavour line only. The left column shows the animated crest, the chosen dragon's name and title, and `DragonStats.make(d)` with the ladder tooltip. Choosing a card updates the `selected` flags and rebuilds only the left column, not the whole screen.
- **Rationale**: Rebuilding everything (as the title screen does today) drops keyboard focus to Continue and restarts the crest; refreshing in place keeps focus on the card the player just chose and avoids flicker (spec edge case on keyboard players). The stats follow the chosen dragon, not focus.
- **Alternatives considered**: Stats inside the chosen card only (cards would change height on every choice, making the grid jump).

## 5. Back from the dragon page

- **Decision**: `DragonScreen.back()` emits `to_title` carrying the options, which updates `menu` so the choice survives; `main.gd` treats `DragonScreen` like `RulesScreen` / `RecordsScreen` for Escape and the system back request.
- **Rationale**: Matches the existing back pattern (FR-012).

## 6. The landing page's look

- **Decision**: Keep the lintel title and the faint woodcut tear; drop the dragon crest from the landing page; the three main buttons stack under the subtitle with Play as `primary`; Settings and Glossary stay as the small `quiet` pair; the disclaimer stays at the foot.
- **Rationale**: Spec assumptions: the moving full-body dragon moves to the dragon page; decoration may stay if it is not a choice.
