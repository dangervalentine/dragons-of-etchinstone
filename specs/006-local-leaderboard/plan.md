# Implementation Plan: Local Play History and Leaderboard

**Branch**: `006-local-leaderboard` | **Date**: 2026-10-15 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/006-local-leaderboard/spec.md`

## Summary

Record every game played on the device (won, lost or abandoned) with its options,
furthest stage, score and active play time, and rank the wins per difficulty with an
optional dragon filter. Records live in a small JSON file in `user://`, written
atomically; a game-in-progress marker, saved after every accepted action and on
every pause, turns a killed game into an Abandoned record at the next launch. Active
time is summed from capped frame times while the play screen is in front and no
menu, rulebook, glossary or dialog is open. A pure `PlayHistory` model does the
ranking, placings, summaries and paging; a new Records screen (Leaderboard and
History tabs, difficulty rail, dragon filter, per-dragon summary) is reached from
the title and ending screens, and the ending screen announces a placing. The engine
and card data do not change.

## Technical Context

**Language/Version**: GDScript, Godot 4.7.2 (standard build)

**Primary Dependencies**: Godot engine only. One new icon (`trophy`) from
`tools/gen_icons.py`. No add-ons.

**Storage**: `user://history.json` and `user://in_progress.json`, JSON, atomic
write-then-rename (research R1–R3). `ui/model/settings.gd` stays as it is and still
provides the last difficulty played.

**Testing**: Headless runner `tools/test.sh` → `tests/run.gd` plus `tools/ui_check.gd`.
New `tests/test_play_clock.gd`, `tests/test_play_history.gd`,
`tests/test_history_store.gd`; `ui_check` extended for the Records screen and for
one record per finished game; `tools/design_shots.gd` extended. Manual checks in
[quickstart.md](quickstart.md).

**Target Platform**: Web (HTML5), Android, iOS; desktop for development.

**Project Type**: Single-project game client (mobile and web), no backend.

**Performance Goals**: Records screen and history open in under 1 s with 500 records
(SC-004); loading and saving 500 records is a few milliseconds, off the per-frame
path (saves happen on actions and pauses only).

**Constraints**:
- `engine/` and `data/cards.json` unchanged; `ui_check`'s engine-agreement checks
  still pass.
- A storage failure never blocks or interrupts play (FR-009).
- Active time within 5 s of real play (SC-002): frame time capped at 1 s (R4).
- Landscape only, 1280 × 720 minimum, text ≥ 22 units, taps ≥ `T.TAP_MIN`, nothing
  scrolls (paged lists instead).
- Tests and tools never touch the player's own records (R10).

**Scale/Scope**: 3 new model modules, 1 new screen, edits to `main.gd`,
`title_screen.gd`, `ending_screen.gd`, `view_state.gd`, `gen_icons.py`,
`ui_check.gd`, `design_shots.gd`, `shot.gd`; 3 new test files. About 900–1,200 lines.

## Implementation Order

Follows the spec's priorities so each story can be shown on its own:

1. **US1 Recording** (P1): `play_clock.gd` + tests → `play_history.gd` record,
   stage and marker functions + tests → `history_store.gd` + tests → `main.gd`
   hooks (load, clock, marker, end, leave, close) → `ui_check` tool dir and
   one-record-per-game check.
2. **US2 Leaderboard** (P1): `board` + tests → `records_screen.gd` Leaderboard tab
   with rail and dragon filter → `trophy` icon and title-screen button → navigation
   and back gesture → `ui_check` walk.
3. **US3 Ending placing** (P2): `placing`, `placing_lines` + tests → view state →
   ending screen lines and Leaderboard button.
4. **US4 History** (P3): `summary`, `page` + tests → History tab with summary panel
   and pager.
5. **US5 Clearing** (P3): `clear_all` + test → Clear records with confirm.
6. Design shots and the quickstart walk-through.

## Risks

| Risk | Mitigation |
|---|---|
| Records lost to a kill during a write | Write-then-rename, `.tmp` fallback, bad file kept (R2); store tests cover each |
| Killed games never recorded on mobile or web | Marker saved after every accepted action and on every pause (R3); quickstart step 5 on each platform |
| Active time inflated by suspend or hidden tabs | Capped frame time (R4); clock tests with a long gap; quickstart step 6 |
| Tools and tests filling the developer's own leaderboard | Store directory overridden in tests and tools (R10) |
| A game recorded twice (won, then close request) | `_recorded` flag per game; `ui_check` asserts exactly one record per played game |
| Records screen too tall at 1280 × 720 with 88-unit taps | Rail of six 88-unit tiles fits 584 units; board rows are text, not buttons; history paged at 6; `ui_check` bounds and no-scroll checks |
