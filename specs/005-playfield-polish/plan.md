# Implementation Plan: Playing Field and Card Polish

## Summary

Rebuild the Mage Card face so it reads as the official printed card: near-black
frame, bevelled top band with an Ether pip, a bronze Key Card strip with torn edges,
a sword spine carrying pennant and shield crests and octagonal action plates, and a
saturated Ether field with real depth. Each Ether gets the official symbol shape and
a foil field like a premium trading card: its own etched texture (Fire licks upward,
Water runs in waves, Lightning zig-zags, Shadow coils under faint stars) under a
faint, slow holographic sheen, drawn by one single-pass shader that holds still
under reduced motion. On that face, a pure
`Emphasis` model decides for every step which regions of each card matter (Armor in
Soak, cost and changed figures in Upgrade, Spell plates / Ether and Initiative /
Boost as each slot comes up) and the face lifts those and quietens the rest without
losing legibility. The play screen gets more air (wider gaps paid for by a slightly
narrower left column, a quieter header), raised panels with the input panel
brought forward, and the inspect overlay shows every Level of a card. The engine and
card data do not change.

## Technical Context

**Language/Version**: GDScript, Godot 4.7.2 (standard build)

**Primary Dependencies**: Godot engine only. Icons from `tools/gen_icons.py`
(Python 3, standard library). No add-ons, no new fonts, no bitmap art.

**Storage**: N/A (the existing motion setting in `ui/model/settings.gd` is reused)

**Testing**: Headless runner `tools/test.sh` → `tests/run.gd` plus `tools/ui_check.gd`.
New: `tests/test_emphasis.gd`, `tests/test_card_contrast.gd`,
`tests/test_card_face_layout.gd`; extended `tests/test_layout_solver.gd`. Screenshots
via `tools/shot.gd` and `tools/design_shots.gd` (extended with an Ether sheet). New
`tools/field_bench.gd` for frame time. Observer checks in [quickstart.md](quickstart.md).

**Target Platform**: Web (HTML5), Android, iOS; desktop for development.
Compatibility renderer (`gl_compatibility`), as today.

**Project Type**: Single-project game client (mobile and web), no backend.

**Performance Goals**: 60 fps with a full Hand of living fields (up to 11 animated
faces: 7-card offer, 3 slots, detail) on a mid-range phone, web build included; all
card fields ≤ 1.5 ms GPU at 1280 × 720 (research D9).

**Constraints**:
- `engine/` and `data/cards.json` unchanged; same outcomes for the same seed and
  choices (FR-028, SC-010; already checked by `tools/ui_check.gd`).
- No scanned or traced official artwork ships; the official look is reproduced
  procedurally (shapes, bands, colour) from observation of `reference/` (git-ignored).
- Minimum text 22 design units, tap target 88; contrast ≥ 4.5:1 text, ≥ 3:1 large
  numerals in every treatment (FR-026).
- Landscape only, one arrangement, 1280 × 720 minimum (FR-017).
- Hand cards no smaller than today at any matrix size (FR-018).
- Reduced motion: still fields, instant emphasis (FR-008, FR-027).

**Scale/Scope**: 1 rebuilt widget (`card_face.gd`), 1 new shader, 1 new pure model
module, edits to about 10 UI files, 4 regenerated Ether icons and sigils, 3 new test
files, 1 new tool. About 1,200–1,600 lines changed.

## Implementation Order

Follows the spec's priorities so each story can be shown on its own:

1. **US1 Card face** (P1): tokens and palette → `gen_icons.py` shapes → field shader
   → `card_face.gd` rebuild with `region_rect` → contrast and face-layout tests →
   inspect overlay (all Levels) → `design_shots` Ether sheet → `field_bench`.
2. **US2 Step emphasis** (P2): `emphasis.gd` + tests (step table, engine agreement)
   → ViewState fields → face treatments and marks → slot focus link → reduced-motion
   path.
3. **US3 Layout** (P3): card-size floor test recorded first → solver constants →
   header → Hand gaps → `input_region` prominence.
4. **US4 Field colour and depth** (P4): raised panels → backdrop and Encounter tint →
   result colour audit.

## Risks

| Risk | Mitigation |
|---|---|
| Living fields stutter on the web build | Budget and bench (D9); fields freeze when covered; octave cap; per-Ether cost measured, worst one simplified first |
| Saturated palette breaks contrast (lightning plate) | `plate_ink` chosen by computed contrast; `test_card_contrast.gd` gates every Ether × treatment |
| Wider gaps shrink cards | Left column narrows to pay; card-size floor test records today's widths before any constant changes |
| Rulebook figures and detail views look wrong with the new face | They use the same `card_face.gd`; `ui_check` walks every rulebook page; screenshot review covers detail and inspect |
| Changing Ether icons shifts other screens (Encounter faces, dragon stats) | Intended (one vocabulary); screenshot matrix reviewed for every screen |
